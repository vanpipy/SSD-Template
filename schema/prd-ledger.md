# PRD Ledger Template (批次 PRD 台账模板)

> **本模板是可选层**: 仅当项目启用 `material/` 素材区 + 批次台账机制时使用. SSD-Template 默认不启用.

---

## 用途

当一个批次 (如 `material/2026-08-19/`) 落盘多份原始素材, 但需要追踪哪些素材已收敛为 PRD、哪些待办、哪些废弃时, 用本表作为「批次 PRD 台账」.

**位置**: `material/{YYYY-MM-DD}/PRDS.md`

---

## 模板

> 字段顺序与名称**严格统一**, 校验脚本按此格式抓取值. 表格前的字段是 ID 前缀路由约定 (见 §字段约定).

| # | ID | PRD 名称 | 优先级 | 验收要点 | 状态 | 来源 | 关联素材 | 创建时间 | 更新时间 | 提出人 |
|---|----|---------|--------|----------|------|------|----------|----------|----------|--------|
| 1 | PRD-20260819-01 | [名称] | P0/P1/P2 | [验收要点] | 待分析/Draft/Ready/Implemented/Deprecated | local/external | [路径或 URL] | [YYYY-MM-DD] | [YYYY-MM-DD] | [github-handle] |
| 2 | PRD-20260819-02 | [名称] | [优先级] | [要点] | [状态] | [来源] | [素材] | [时间] | [时间] | [人] |

---

## 字段约定

| 字段 | 必填 | 说明 |
|------|------|------|
| **#** | ✓ | 序号 (1-based) |
| **ID** | ✓ | 唯一标识, 格式 `{prefix}-{YYYYMMDD}-{NN}` |
| **PRD 名称** | ✓ | 主题, 简短描述 |
| **优先级** | ✓ | P0 (核心) / P1 (重要) / P2 (辅助) / 待定 (人工尚未评估) |
| **验收要点** | ✓ | 1-2 句话概括该 PRD 的核心验收标准 |
| **状态** | ✓ | 待分析 / Draft / Ready / Implemented / Deprecated |
| **来源** | ✓ | `local` (本地素材) / `external` (外部来源, URL) / `internal` (内部转写) |
| **关联素材** | ✓ | 路径 (仓内) 或 URL (仓外) |
| **创建时间** | ✓ | 该 PRD 行首次登记日期 |
| **更新时间** | ✓ | 该 PRD 行最近一次更新日期 |
| **提出人** | ✓ | 登记人 github-handle, 待补填 `[待补]` |

---

## ID 前缀约定

| 前缀 | 流水线入口 | 说明 |
|------|------------|------|
| **PRD-** | `/to-prd` | 需求文档 → 进入 PRD 收敛流程 |
| **TECH-** | `/to-tech-design` | 技术文档 (方案/接口/设计/调研) → 进入 Tech Design 流程 |
| **TEST-** | `/to-test-cases` | 测试用例文档 → 进入 Test Case 流程 |
| **PLAN-** | `/to-plan` | 实施 Plan 文档 → 进入 Plan 流程 |

> **路由规则**: 素材 ID 前缀决定流水线入口. 例如 `PRD-20260819-01` 对应素材由 `/to-prd` skill 处理.

---

## 哨兵定义 (用于自动化巡检)

| 哨兵 | 判定条件 | 处置 |
|------|----------|------|
| **待分析** | `优先级=待定` 或 `提出人=[待补]` | L2 (agent) 读素材原文充实行 |
| **待抓取** | `来源=external` 且有 URL 但 `创建时间` 为空 | L2 编排外部抓取 (项目自定义 skill) |
