# Tech Design: [主题]

> **视角：执行 Agent — 关注策略、指标、调查、兜底**
> Tech Design 是业务规则到代码实现之间的桥梁。它的核心职责是：
> - **策略**：明确技术路线和架构方向。不只是"选什么"，而是"整体怎么建"——包括技术路线选择、集成模式、数据管理策略、部署与扩展方式。每个策略决策必须有备选方案和选择理由。
> - **指标**：定义可衡量的技术目标。不写"高性能"，写具体的延迟、吞吐、可用性、容量数字。指标是验收的标准，也是设计决策的约束条件。
> - **调查**：在方案层级对过程进行全量细致的调查。不只是"主流程能跑通"，而是把每一个环节展开到可审查的粒度——输入从哪来、处理逻辑是什么、输出到哪去、什么条件下会失败、失败后影响什么。Agent 通过调查知道方案的全貌，而非只看到主干。
> - **兜底**：确保需求转换后业务意图不丢失。每个 Collection 场景必须有对应的技术路径；如果技术上无法完全实现，必须明确降级方案并说明对业务的影响。Agent 根据兜底策略知道什么时候走正常路径、什么时候走降级路径。
