# 批次概览: [主题]

> **视角：拆分批次的 Agent（Prompt 1 / Prompt 2）**
> 批次概览是 **Agent 的工作产物**，在将输入拆分为 Collection 时产出。它服务三类读者：
> - **参与人（审阅者）**：Agent 提议拆分后读一次，确认拆分是否合理（数量、边界、关系都合适）。后续不主动维护。
> - **收敛 Agent（Prompt 3）**：读取作为全局上下文，理解跨 Collection 的耦合关系。
> - **技术设计 Agent（Prompt 4）**：读取以理解共享数据模型、共享基础设施和架构约束，再深入某个 Collection。
>
> 一个批次只有一份批次概览，由 Agent 随 Collection 变化同步更新。

> 本模板分为**必填区**和**补充区**。
> - **必填区**：Agent 在创建批次时必须填写。
> - **补充区**：Agent 在后续收敛过程中随 Collection 更新同步补全。

---

## 草稿审阅协议

> 批次概览分两轮产出，中间设有显式审阅节点。

**第一轮 — Agent 提议拆分（状态：草稿）**
1. Agent 读取输入（会议摘要 / 需求集合）。
2. Agent 应用 Prompt 1 Step 1 中的拆分/合并决策原则。
3. Agent 仅起草**批次元数据 + Collection 清单 + 跨 Collection 关系**三个区块（暂不起草全局待收敛清单）。
4. Agent 向参与人呈现：
   - 提议的拆分数量与理由。
   - Collection 清单表。
   - 跨 Collection 关系图。
   - "我不确定的拆分决策"清单（如果有）。

**审阅节点 — 参与人审阅**
- 参与人可以选择：(a) 接受当前拆分；(b) 要求合并/拆分（例如"C03 和 C04 应该合并成一个 Collection"）；(c) 要求按轻量模式重新拆分。
- Agent 按反馈调整清单和关系。

**第二轮 — Agent 起草 Collection + 全局待收敛清单（状态：采集中）**
1. Agent 按 schema/collection-cn.md 起草每个 Collection，对不确定的字段标注 `⚠`。
2. Agent 在批次概览中产出**全局待收敛清单**（汇总所有草稿 Collection 中的模糊点）。
3. Agent 在输入材料允许的范围内产出**补充区**（外部依赖、架构决策、主题）。
4. Agent 向参与人进行第二轮呈现 — 本次聚焦 Collection *内容*，而非拆分结构。
5. 参与人解决 `⚠` 标记；每个审阅过的 Collection 状态由草稿翻为采集中。

**轻量模式捷径**：触发条件满足时（见 schema/collection-cn.md），第一轮与第二轮可合并为一轮，因为拆分规模很小。Agent 仍须在本文件顶部显式说明轻量模式理由。

### 跨 Collection 关系

> 描述 Collection 之间的调用/依赖/共享关系。优先用简图，复杂情况再补文字说明。

```
[C01] --[关系类型]--> [C02]
```

#### 关系类型说明
- **前置依赖（prerequisite）**: 必须先完成 A 才能启动 B（顺序关系）
- **数据共享（data-sharing）**: A 和 B 读写同一份数据/模型
- **调用关系（invocation）**: A 在业务流程中直接触发 B
- **约束（constraint）**: A 的决策或规则限制了 B 的设计空间（如架构决策约束场景设计）
- **替代方案（alternative）**: A 和 B 是同一问题的互斥选项（最终只选其一）
- **运行时互斥（mutually-exclusive）**: A 和 B 不会在同一次执行中发生（与"替代方案"不同——两者可能都存在）

### 全局待收敛清单

> 汇总所有 Collection 中尚未解决的模糊点，附来源链接与优先级。参与人集中讨论时看这里，不要挨个打开 Collection。

#### 优先级说明
- **P0**: 阻塞 Tech Design 启动（如核心架构决策、基础数据模型）
- **P1**: 阻塞一条或多条已收敛规则，但不阻塞整个批次
- **P2**: 优化/边缘场景 — 可延后处理，不阻塞下游工作
