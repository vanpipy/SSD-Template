# Collection: [主题]

> **视角：审阅者（参与人）+ 起草者（Agent）**
> Collection 是两个角色共同维护的产物：
> - **Agent（起草者）**：从输入（会议摘要、原始需求、代码）中提取事实，尽可能结构化地起草 Collection，对任何不确定的内容标注 `⚠ 待确认`，让参与人知道哪里需要他做判断。
> - **参与人（审阅者 + 决策者）**：对照实际讨论内容验证草稿，解决 `⚠` 标记，补充 agent 无法推断的内容，对模糊点做最终决策。
>
> 这样分工的原因是：agent 擅长结构化与穷举提取，但不擅长判断"到底达成了什么共识"。参与人才是共识的来源。
>
> **起草原则（Agent）**：
> - 只起草能在输入中找到依据的内容。任何推断但未明说的部分，标注 `⚠`。
> - Given/When/Then 是帮你发现"我到底想清楚没有"的工具，不是格式要求。如果一条规则你写不出 Then，就放进待收敛模糊点。
> - 宁可多写待收敛模糊点，也不要把未经确认的内容写成已收敛规则。
>
> **审阅原则（参与人）**：
> - 你不是在重写，而是在验证和决策。草稿错了就改，对了就去掉 `⚠`，缺了就补。
> - 不要添加讨论中未提及的事实。如果某事不清楚，加一条待收敛模糊点，而不是自己编答案。
>
> 本模板分为**必填区**和**补充区**。
> - **必填区**：创建采集时必须填写（由 agent 起草 + 参与人审阅）。这是 Collection 的核心内容。
> - **补充区**：在收敛讨论过程中逐步补充，不必在创建时填写。

## 必填区

### 原始诉求

[用户的原始原话或需求方的最初描述。保留原始语境和表达方式，不做改写。可以是一段话、一句话、甚至一句抱怨。]

### 讨论范围
- 聚焦: [本次讨论覆盖的业务领域和功能边界]
- 不涉及: [明确排除的内容。如果会议或需求中明确说了"这个不做"、"一期不做"、"不归我们管"，必须写在这里]

### 已收敛规则

> 每条规则描述一个已达成共识的业务/技术事实。根据内容性质选择对应格式：
> - **场景类**（用户交互/业务流转）→ 用 Given/When/Then。Then 必须包含可验证的具体条件，不允许使用"完成 XX"、"支持 XX"等笼统描述。如果无法写出具体条件，说明尚未收敛，应放入待收敛模糊点。
> - **架构决策类**（技术选型/模式选择）→ 用"决策/备选/选择/理由"。
> - **业务约束类**（必须满足的硬性条件，非场景）→ 用自然语言 + 影响范围。

#### 场景: [场景名称]
- Given [前置条件 — 什么情况下触发]
- When [触发动作 — 谁做了什么]
- Then [预期结果 — 系统具体产生什么变化，可被验证]

#### 架构决策: [决策名称]
- 决策: [需要确定的核心问题]
- 备选: [讨论过的可选方案]
- 选择: [最终决定]
- 理由: [为什么这样选]

#### 业务约束: [约束名称]
- 约束: [必须满足的硬性条件，自然语言描述]
- 影响: [这条约束对哪些下游规则/场景有影响]

### 待收敛模糊点

> 记录所有尚未明确的点。每个模糊点必须说明它阻塞了什么——如果不解决，哪条规则写不出来。

- [问题] — 阻塞: [哪条规则的收敛被这个问题阻塞了] — 备注: [已有线索或可能方向，可选]

## 收敛检查

> 将状态改为「已收敛」前，逐项确认。全部满足才能改状态。

- [ ] 每个场景类 Then 包含可验证的具体条件（无"完成 XX"、"支持 XX"等笼统描述）
- [ ] 每个架构决策类都有备选方案和选择理由
- [ ] 每个业务约束类都标注了影响范围
- [ ] 适用范围内的主要场景已覆盖（正常路径 + 至少一条异常路径）
- [ ] 待收敛模糊点已全部清零（决策完毕并转化为规则，或明确标记为延迟决策）
- [ ] 已收敛规则之间无逻辑矛盾
- [ ] 依赖关系已确认（已填写或明确标注"无"）

## 轻量模式（适用于小型批次）

> 当批次内**独立需求点 ≤ 4 个 且 不存在跨角色/跨系统耦合**时，agent 可采用简化 Collection：
> - 将相关场景合并为单个 Collection，而非按能力边界拆分。
> - 待收敛模糊点可以是扁平的列表，不必逐条标注"阻塞哪条规则"（鼓励标注但不强制）。
> - 补充区如无内容可完全省略。
>
> 批次级别的 BATCH-OVERVIEW 仍然产出，但为简化版（仅保留 inventory 表 + 关系图，不要求主题分组和全局待收敛清单）。
> 适用轻量模式时，agent 必须在 BATCH-OVERVIEW 顶部显式说明"使用轻量模式，原因：[理由]"。
