# 评审检查清单

Step 5 评审时按以下维度逐项检查。

## 1. 覆盖度

- [ ] 功能点清单中每个点都有对应用例
- [ ] P0 功能点 100% 覆盖
- [ ] 每个功能点的主路径 + 至少 1 个异常路径
- [ ] PRD Out of Scope 的内容未被误测
- [ ] **PRD 每个 But 分支都有 ≥1 条用例（先 `grep -c '\*\*But\*\*'` 数）(v2.3)**
- [ ] **环境边界 Checklist 逐维对照无遗漏（网络/系统声道/生命周期/权限角色/数据边界）(v2.3)**
- [ ] **PRD Goal 显式默认值有初始状态用例 (v2.3)**
- [ ] **TD exploration OQ 点名 TC 的收敛用例已生成并标注 OQ 关联 (v2.3)**

## 2. 优先级合理性

- [ ] P0 数量合理（不超过总数 30%）
- [ ] 优先级与关键程度 × 使用频率矩阵匹配
- [ ] 低价值场景未误标 P0
- [ ] 关键功能未漏标为 P2/P3

## 3. 用例质量

- [ ] 步骤具体可执行（避免"正常操作"式描述）
- [ ] 预期可观察/可判定（UI/接口/DB 至少一类）
- [ ] 前置条件充分（环境 + 数据 + 账号）
- [ ] 无重复冗余用例
- [ ] 每个用例验证一个点（原子性）

## 4. 方法论覆盖

- [ ] 有输入字段的功能：等价类有效/无效分区完整
- [ ] 有数值/长度/时间约束：边界值 ±1 覆盖
- [ ] 有状态流转：合法迁移 + 非法迁移都覆盖
- [ ] 多条件判断：判定表组合覆盖
- [ ] 所有功能：错误推测（空值/超时/并发/重复）

## 5. 平台特异性

- [ ] 目标平台的交互差异已覆盖
- [ ] 平台特有权限/生命周期已覆盖
- [ ] 未重复通用逻辑
- [ ] platform-specific 用例有 platform_notes

## 6. 业务规则覆盖（若 _rules.md 存在）

- [ ] 每条 P0/P1 业务规则有对应用例
- [ ] 遗漏标注"规则 {ID} 缺少对应用例"
- [ ] 新用例与已有规则不冲突

## 7. 格式合规

- [ ] Markdown 结构符合 `schema/test_case.md`（v2.1+ 输出口径为 Markdown）
- [ ] ID 编号连续无重复
- [ ] Suite 按功能模块合理分组
- [ ] tags 标注来源 PRD 场景编号
