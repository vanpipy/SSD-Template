# Step 1: Confirming Phase

确认所有前置信息，缺一不可。

## 必须交互确认的 5 项

### 1. 输入确认

- "PRD 路径是？"
- "Tech Design 路径是？"
- "PRD 和技术设计是否已经过研发审核？"（否 → **中止**，提示先完成审核）

若用户未提供路径参数，询问：
- 是否有 PRD？路径或直接描述需求变更
- 是否有 Tech Design？路径

### 2. 业务产品信息

- "本次需求所属的业务产品是什么？"
- 让用户描述业务类别（如"桌面端 X 终端"、"移动端 Y App"、"扫码设备 Z"）
- 根据描述拼接产品目录名（小写连字符，如 `my-product`、`my-product-mobile`）
- 向用户确认拼接的目录名是否正确

### 3. 目标平台

- "本次要生成哪个平台的测试用例？"
- 选项：iOS / Android / Windows / macOS / Web / HarmonyOS / 其他
- **每次只选一个平台**

### 4. 范围确认

- "需要全量覆盖还是仅覆盖特定模块/场景？"
- 若选特定模块 → 追问具体模块列表

### 5. 优先级策略

- "P0/P1 用例需要达到什么覆盖水平？"
- 默认：P0 100% 覆盖主路径，P1 覆盖所有分支

### 6. 执行范围

若用户未通过参数指定，询问：
- "本次需要完整生成用例，还是只分析功能点，或者只出 P0 冒烟用例？"
- 选项：
  - **full**（默认）：完整流程
  - **analyze**：只提取功能点 + 优先级建议，不生成用例
  - **smoke**：仅生成 P0 主路径冒烟用例

## 无 PRD 场景（优化/增强）

若用户表示没有 PRD：
1. 询问需求变更描述
2. 询问是否有技术设计文档
3. 询问影响范围（哪些页面/模块）
4. 基于描述提取测试点，继续标准流程

## 确认后输出

```
✅ 确认完成：
- PRD：{path}
- Tech Design：{path}
- 研发审核：已确认
- 业务产品：{product-name}
- 目标平台：{platform}
- 范围：{全量/指定模块}
- 优先级策略：{默认/自定义}
- 执行范围：{full/analyze/smoke}

→ 进入 Step 2: Resolving Business
```
