# Step 5: Reviewing Phase

> 多角色独立评审 → 自动修改循环（≤3 轮）→ 用户确认
>
> **业务上下文**：所有角色基于传入的 PRD + Tech Design 文档中的业务描述进行分析，不依赖外部业务知识。
>
> **输入来源**：仅使用 Step 3 提取结果 + Step 4 生成的用例，不重读源文档。

## 评审角色定义

每轮评审由 **4 个独立角色** 分别从各自专业视角审查，角色之间不共享判断：

### 角色 1：业务分析师（BA Reviewer）

**职责**：验证用例是否完整覆盖业务需求

- 对照 PRD Scenarios 逐条检查：每个 Given/When/Then 是否有对应用例
- 对照 PRD Goal：验收标准是否全部可测
- 对照 Out of Scope：是否有误测排除范围
- 检查业务规则覆盖：`_rules.md` 中 P0/P1 规则是否逐条有用例
- **输出**：业务覆盖度报告（已覆盖/部分覆盖/缺失）

### 角色 2：测试架构师（Test Architect）

**职责**：验证用例设计方法论的完整性和分层合理性

- 方法论覆盖：等价类/边界值/状态迁移/判定表/错误推测是否按需使用
- 分层完整性：每个功能点是否有前端/后端/E2E 三层用例
- 前后端连接：前端传参 ↔ 后端契约、后端返回 ↔ 前端展示是否闭环
- 用例原子性：是否存在一个用例验证多个点
- **输出**：方法论覆盖度 + 分层完整性报告

### 角色 3：系统工程师（System Engineer）

**职责**：结合系统架构和技术实现验证用例的技术深度

- 对照 Tech Design `apis.md`：接口参数边界是否覆盖（存量 v3 TD：`api-contracts.md`）
- 对照 `ards.md`：技术约束（并发/幂等/事务）是否有对应异常用例（存量 v3 TD：`decisions.md`）
- 对照 README「质量保证」段：性能/安全要求是否有对应用例（存量 v3 TD：`quality.md`）
- 对照 `data-model.md`：数据约束（字段长度/类型/关联）是否覆盖
- 平台特异性：目标平台的系统级场景是否覆盖（生命周期/权限/网络）
- **输出**：技术覆盖度 + 平台特异性报告

### 角色 4：用户体验评审员（UX Reviewer）

**职责**：从最终用户视角验证用例的可执行性和体验覆盖

- 步骤可执行性：是否具体到页面/按钮/输入值（避免"正常操作"）
- 预期可判定性：是否可观察（UI 变化/提示文案/接口响应）
- 交互体验覆盖：加载态/空状态/错误提示/操作反馈是否有用例
- 优先级合理性：P0 是否过多/过少，是否匹配使用频率 × 关键程度
- **输出**：可执行性 + 优先级合理性报告

## 评审循环流程

```
┌─────────────────────────────────────────────────────┐
│ 第 N 轮评审                                          │
│                                                     │
│  BA Reviewer ──→ 业务覆盖度报告                      │
│  Test Architect ──→ 方法论/分层报告                   │
│  System Engineer ──→ 技术覆盖度报告                   │
│  UX Reviewer ──→ 可执行性/优先级报告                  │
│                                                     │
│  汇总 4 份报告 → 合并修改建议清单                     │
│       ↓                                             │
│  有明确问题？ → 自动修改 → 第 N+1 轮                 │
│  无问题？ → 跳出循环                                 │
└─────────────────────────────────────────────────────┘
         ↓ 循环结束
   强制暂停 → 用户确认
```

### 终止条件

- 4 个角色均无明确问题（仅有"待确认"项不算问题），或
- 达到 3 轮上限

## 评审报告格式

```markdown
# 用例评审报告 v{N}

## 评审摘要
- 用例总数：N（前端 N / 后端 N / E2E N）
- 问题总数：N
- 风险等级：高/中/低

## 1. 业务覆盖度（BA Reviewer）
| PRD 场景 | 状态 | 对应用例 | 备注 |
|----------|------|---------|------|

## 2. 方法论与分层（Test Architect）
| 功能点 | 前端 | 后端 | E2E | 缺失方法 |
|--------|------|------|-----|---------|

## 3. 技术覆盖度（System Engineer）
| 技术约束 | 来源 | 对应用例 | 状态 |
|----------|------|---------|------|

## 4. 可执行性与优先级（UX Reviewer）
| 用例 ID | 问题 | 建议 |
|---------|------|------|

## 5. 修改建议清单（汇总）
| # | 角色 | 定位 | 问题 | 建议 |
|---|------|------|------|------|
```

## 用户确认（强制暂停）

循环结束后：

```
已完成 N 轮多角色评审，当前版本 v{最终版本}。

评审摘要：
- BA：业务覆盖 100%，无缺失
- 架构师：补充 2 个后端幂等用例
- 工程师：补充 1 个平台生命周期用例
- UX：修正 3 个优先级

是否确认？
1. 确认 → 进入 Step 6
2. 需要修改 → 请指出
```
