# Step 4: Generating Phase

> **角色**：资深测试架构师，精通黑盒测试方法论、前后端分离架构测试、端到端链路验证。
>
> **输入来源**：仅使用 Step 3 提取的功能点清单和工作上下文，不重读 PRD/TD 源文档。

## 测试分层模型

每个功能点必须按三层拆解用例，确保前后端连接完整：

```
┌─────────────────────────────────────────────────┐
│  E2E 端到端层（用户视角）                         │
│  前端操作 → 接口调用 → 后端处理 → 数据落库 → 前端反馈 │
├─────────────────────────────────────────────────┤
│  前端层（UI/交互）          │  后端层（接口/逻辑）  │
│  输入校验、状态展示、       │  入参校验、业务规则、  │
│  交互反馈、页面跳转        │  数据一致性、异常处理  │
└─────────────────────────────────────────────────┘
```

### 三层用例职责

| 层 | 验证什么 | 典型用例 | type 标注 |
|----|---------|---------|-----------|
| **前端** | UI 交互、输入校验、状态展示、页面跳转 | 空输入提示、按钮禁用、加载态 | `frontend` |
| **后端** | 接口入参/出参、业务规则、数据落库、异常码 | 参数越界、并发幂等、事务回滚 | `backend` |
| **端到端** | 用户操作全链路贯通、前后端数据一致 | 提交→成功→列表刷新→数据正确 | `e2e` |

### 前后端连接逻辑

每个功能点必须验证**前端 → 后端 → 前端**的完整闭环：

```
前端触发 → 请求参数正确性 → 后端处理逻辑 → 响应数据正确性 → 前端展示正确性
```

**连接点检查**：
- 前端传参格式是否与后端接口契约一致
- 后端返回码前端是否全部处理（成功/失败/超时）
- 前端展示字段是否与后端返回字段对应
- 异常场景前端是否有兜底（网络断开、服务不可用）

## 方法论矩阵

| 功能特征 | 适用方法 | 前端层产出 | 后端层产出 | E2E 产出 |
|----------|---------|-----------|-----------|---------|
| 有输入字段 | 等价类 + 边界值 | 输入校验提示 | 参数越界拒绝 | 非法输入全链路拦截 |
| 有状态流转 | 状态迁移 | 状态 UI 展示 | 非法迁移拒绝 | 状态变更全链路同步 |
| 多条件判断 | 判定表 | 条件组合 UI 联动 | 条件组合逻辑正确 | 组合条件全链路 |
| 用户操作流 | 场景法 | 页面跳转/交互 | 接口调用链 | 端到端主路径 |
| 所有功能 | 错误推测 | 异常 UI 兜底 | 异常码/降级 | 异常全链路表现 |

## But 覆盖与环境边界（v2.3，强制）

### But 逐条覆盖

Step 3 提取的 But 分支清单，**每个 But 必须有 ≥1 条用例**（通常落在 E2E 层），用例 tags 标注对应 PRD 场景与分支（如 `S-2-But1`）。But 是验收边界的一等来源，漏 But = 验收漏测。

### 环境边界 Checklist

逐维对照，PRD 的 But 通常落在这些维度，没覆盖到的维度要回查 PRD/TD 是否有对应分支：

| 维度 | 典型边界 | 示例（pay-voice）|
|------|---------|----------------|
| 网络 | 弱网 / 离线 / 网络切换 | 离线收款正常播报（不依赖网络）|
| 系统声道 | 静音 / 最低音量 / 外放设备切换 | 静音时遵循系统声道，不强提音量不报错 |
| 生命周期 | 重启 / 后台 / 进程被杀 | 重启后配置保持（本地持久化）|
| 权限/角色 | 不同角色 / 未授权 | —（按需求适用性判断）|
| 数据边界 | 空数据 / 边界金额 / 极值 | 0.01 元最小金额播报 |

### 默认值用例

PRD Goal 的显式默认值（总开关默认开、音量默认 60 等）必须有**初始状态验证用例**（首次启动/恢复默认后观察）。

### OQ 收敛用例

TD ards.md「探索记录」的 OQ 收敛方式若点名测试用例（如「TC-xxx 离线冒烟收敛 OQ-4」），必须生成对应用例，并在用例备注标注 OQ 关联（如「收敛 ards OQ-4」）。（存量 v3 TD：exploration.md）

## 生成流程

```
功能点
  → 拆解为前端/后端/E2E 三层测试点
  → 确定每层适用方法
  → 逐方法生成用例
  → But 逐条对账 + 环境边界 Checklist 对照 (v2.3)
  → 验证前后端连接点
  → 合并去重
  → 标注优先级
  → 注入平台特异性
```

### smoke 模式裁剪

若执行范围为 `smoke`，仅生成 P0 用例：
- 每个功能点只保留 **E2E 主路径**（1-2 条）
- 跳过前端细节用例、边界值、错误推测
- 跳过后端参数越界、并发、幂等等非主路径
- 跳过平台特异性注入
- 不叠加系统知识库
- 目标：最小可执行冒烟集，验证核心链路贯通

## 用例构建要求

### 前端用例

- 步骤描述用户操作（点击/输入/滑动）
- 预期为 UI 可观察结果（提示文案/按钮状态/页面跳转）
- 覆盖：空值、格式错误、超长输入、特殊字符、重复点击

### 后端用例

- 步骤描述接口调用（请求方法/路径/参数）
- 预期为接口响应（状态码/返回体/错误码）+ 数据层验证（DB 状态）
- 覆盖：参数越界、必填缺失、类型错误、并发、幂等、事务

### E2E 用例

- 步骤从用户操作开始，到 UI 反馈结束
- 预期包含全链路验证：UI 变化 + 接口响应 + 数据落库
- 覆盖：主路径贯通、异常路径用户感知、数据前后端一致

## 优先级标注

按 `references/priority-matrix.md` 中的矩阵标注。

**层级优先级规则**：
- E2E 主路径 → 至少 P0
- 后端核心业务规则 → 至少 P1
- 前端交互细节 → P2/P3（除非影响核心流程）

## 平台特异性注入

生成通用用例后，按目标平台补充差异用例。详见 `references/platform-dimensions.md`。

- 仅补充该平台**特有的**差异用例
- 标注 `type: "platform-specific"`

## 业务规则叠加

若 `test-business/{product}/_rules.md` 存在：
- 读取已有业务规则
- 生成用例时自动应用
- 确保新用例与已有规则不冲突

## 系统知识库叠加

读取 `references/system-knowledge.md` 中当前业务产品对应段落：
- **线上崩溃数据** → 转化为回归测试用例（type: error）
- **复杂操作问题** → 转化为错误推测用例（method: error-guess）
- **测试遗留难题** → 在相关功能点下标注“已知风险”
- 已修复的问题仍生成回归用例，标注 `[回归]` tag

## 用例原子性

- 每个用例验证**一个点**
- 不合并多步验证到一个用例
- expected 必须可观察（UI 变化/接口返回/DB 状态，至少一类）

## 输出

生成完成后进入 Step 5 评审，不直接写文件。
