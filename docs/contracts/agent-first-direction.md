# 需求集：SDD 流程方向调整（agent 为主、人类为辅）

> 本文件是本轮分析的**唯一真源**。任何结论必须能指回下面某个 R 编号。
> 来源 = 用户指令 m01855：「ssd流程是以agent为主，人类为辅的自动化运行系统，你的核心发现证明了当前流程是残缺的，现在需要调整方向，请先进行深度分析」

---

## R1 方向基线澄清

流程的**设计意图**是 agent 为主、人类为辅的自动化运行系统；现状与该意图不符，本轮产出必须回答「差在哪里、怎么调」。

check: 分析文档明确写出「agent 为主、人类为辅」的**可检验定义**（人类角色的类型、频次、信息载荷、是否阻塞流水线），且每个定义项都能对应到现状证据。
source: 用户指令 m01855

---

## R2 人类介入点全量盘点

找出当前流程中**全部**人类介入点（含闸门、状态回写、裁决、素材供给），并区分「人类作为流水线节拍器」与「人类作为决策者/例外处理者」。

check: 一张完整清单，每个介入点带 file:line、触发时机、信息载荷（人要读多少才能决策）、是否阻塞下游。
source: 用户指令 m01855 + 既有分析 docs/process-analysis.md

---

## R3 根因分离

区分三类根因，避免把它们混为一谈：
(a) 机器判据不足（内容层 0 断言）；
(b) 状态推进无机器写路径（编排层闸门缺失、blocked_by 死数据）；
(c) 人类介入界面缺失（没有「人只需裁决」的最小单元）。

check: 每类根因给出独立证据、独立修复方向、独立的验收方式；不得用「补机器门禁」一刀切解释全部缺陷。
source: 既有分析 docs/process-analysis.md §断点 + docs/operation-flow.md

---

## R4 目标架构

给出 agent-first 目标架构：状态与调度谓词的正交化、机器判据层、内容断言层、编排层闸门、人类裁决入口、证据与审计链。

check: 目标架构每个组件都标注「现状是否存在 / 缺失 / 与现状冲突」，并给出现状→目标的可追溯映射表。
source: 用户指令 m01855

---

## R5 分期路线与优先级

给出可执行的分期（不是泛泛建议），每期含：改动面、依赖、验收命令、可回退性、对「人工介入次数/特性」的量化影响。

check: 每期都给出**可测的量化指标变化**（至少一项），且给出该指标的当前基线值。
source: 用户指令 m01855

---

## R6 待决项

列出必须由用户拍板的设计决策（含此前挂起的三项：Ready 闸门归属 / docs 入 git / issue 控制平面位置），并对每一项给出推荐默认值 + 理由 + 若选另一分支的后果。

check: 每个待决项都有明确问题句、默认推荐、备选后果；不含开放式「你觉得呢」。
source: 用户指令 m01855 + 既有挂起项
