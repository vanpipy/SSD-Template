## 为什么 (Why)

规格仓里每层产物(PRD / Tech Design / Plan)的必填项分散在 `schema/**` 模板与 `scripts/**` 校验脚本两处,两处一旦漂移就没有单一真源。产出者(人或 agent)写完一层产物后,只能靠人工逐段比对才知道漏了哪一项;漏项要等门禁报错才暴露,返工成本高。

## 目标 (Goal)

- [ ] AC-1 每层产物有一份可直接勾选的自检清单,清单项与该层 `schema/**` 的机器必填项一一对应
- [ ] AC-2 清单任一项缺失时,自检结论明确指出缺哪一项,而不是给出「全部通过」
- [ ] AC-3 清单全部勾选通过时,该层校验脚本的退出码为 0
- [ ] AC-4 增删 `schema/**` 的必填项时,清单可在同一次提交内同步更新

## 场景 (Scenarios)

### 场景: S-1 产出 PRD 后逐项自检

**覆盖**: AC-1, AC-2

**Given** 一份状态为 Draft 的 PRD 已写入 `prd/2026-11-22/layer-checklist.md`
**When** 产出者按 PRD 层自检清单逐条核对必填段
**Then** 清单列出的每一项在该 PRD 中都能定位到对应段落
**But** 若 PRD 缺少 `## 不在范围内 (Out of Scope)` 段,自检必须报出「缺失:不在范围内」,不得给出「全部通过」

### 场景: S-2 自检结论与门禁结论一致

**覆盖**: AC-3

**Given** 某层产物的自检清单全部勾选通过
**When** 在仓根运行该层的校验脚本
**Then** 脚本退出码为 0

### 场景: S-3 模板必填项变更

**覆盖**: AC-4

**Given** `schema/plan.md` 新增了一个机器必填段
**When** Plan 层自检清单在同一次提交中更新
**Then** 清单项数与 `scripts/check-md-schema.sh` 实际校验的段数一致

## 不在范围内 (Out of Scope)

- 不新增或修改任何校验脚本 —— 自检清单是文档,机器判定仍由既有脚本承担
- 不改变任何层的状态枚举与状态机
- 不做勾选界面的 UI 化
