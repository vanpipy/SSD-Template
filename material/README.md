# Material(素材区)

> **Layer 0(可选)**。原始素材暂存 + 批次 PRD 台账。**默认关闭** —— 目录不存在时,相关校验自动跳过。
> 架构层只有 Layer 1 / 2 / 3;素材区不是独立架构层。

## 什么时候启用

| 场景 | 是否需要素材区 |
|------|----------------|
| 素材直接放 `prd/{YYYY-MM-DD}/`,一个批次只产出少量 PRD | **不需要** —— 用 `prd/` 自带的素材存放区即可 |
| 一个批次落盘多份素材,需要追踪「哪份素材已收敛成 PRD、哪份待办」 | **需要** —— 素材区 + 批次台账 |
| 需要登记外部来源(URL)并安排抓取 | **需要** —— 台账 `来源` 列取 `external` |

> 素材长期暂存时,建议从 `prd/{YYYY-MM-DD}/` 迁到 `material/{YYYY-MM-DD}/`,让 `prd/` 只留 Layer 1 制品。

## 文件夹结构

```text
material/
├── README.md
└── {YYYY-MM-DD}/               ← 批次目录(日期分桶)
    ├── {source-1}.md           ← 原始素材(只读,非层制品)
    ├── {source-2}.md
    └── PRDS.md                 ← 批次 PRD 台账(可选)
```

**目录命名**: `{YYYY-MM-DD}`,必须是规范日期(`^[0-9]{4}-[0-9]{2}-[0-9]{2}$`)。
**素材命名**: `{来源描述}.md`,可多个,不强制 topic 格式。
**层根只允许** `README.md` 与 `_index.md`;批次目录下是素材与台账,深度不得再深。

## 批次 PRD 台账

位置 `material/{YYYY-MM-DD}/PRDS.md`,11 列固定格式:

| # | ID | PRD 名称 | 优先级 | 验收要点 | 状态 | 来源 | 关联素材 | 创建时间 | 更新时间 | 提出人 |
|---|----|---------|--------|----------|------|------|----------|----------|----------|--------|

- **ID** 格式 `{前缀}-{YYYYMMDD}-{NN}`,前缀 `PRD-` / `TECH-` / `TEST-` / `PLAN-` 决定流水线入口
- **状态** 取值 `待分析` / `Draft` / `Ready` / `Implemented` / `Deprecated`;其中 `待分析` 是**台账哨兵**(素材尚未收敛成 PRD),不是层生命周期状态
- **来源** 只有 `local` / `external` / `internal` 三值
- **提出人** 是登记人 handle;不知道就写 `[待补]`,**不得编造**

模板与字段约定见 [schema/prd-ledger.md](../schema/prd-ledger.md)。

## 脚本

| 脚本 | 作用 |
|------|------|
| `scripts/sync-prd.sh` | 补登台账骨架行、标记待办行(`待分析` / `待抓取` / 孤儿行)、幂等再生成根 README 的统计块 |
| `scripts/check-traceability.py` | 台账存在时校验 ID 格式与 `## PRD台账` 段 |

> `sync-prd.sh` **不做任何 git 写操作**,只改工作区文件;退出码 `1` 表示存在待办行(台账待办信号),不是失败。
